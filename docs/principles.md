# 원칙

상태: 이 문서는 현재 구현을 기술한다

## 1. 배포 유연성이 최우선이다

Sendway는 관리형 클라우드 환경과 온프레미스 환경 모두에서 동일하게 동작해야 합니다. 특정 클라우드 벤더 전용 기능에 의존하지 않습니다.

**대가**: 이 원칙 때문에 통합 속도(3번)가 희생되는 경우가 있습니다 — 온프레미스 대응이 필요한 설계 결정은 클라우드 전용 구현보다 시간이 걸립니다.

## 2. 얇은 책임 경계를 지킨다

Sendway는 발송만 책임집니다. 수신자 신원, 구독 설정, 조직/테넌시 같은 개념은 다루지 않습니다.

**대가**: "이 정도는 Sendway가 대신 처리해주면 편한데"라는 요청을 거절해야 하는 경우가 생깁니다.

## 3. 통합 속도를 지킨다

새 서비스가 Sendway를 붙이는 데 드는 시간을 최소화합니다.

**대가**: 위 두 원칙과 충돌할 때는 통합 속도가 밀립니다.
