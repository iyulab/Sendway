# 운영

Sendway를 직접 띄워 운영할 때 필요한 절차입니다. 대기열 상태와 로그로 서비스를 지켜보는 방법은 [아키텍처](architecture.md)의 「운영」에 있습니다.

## 비밀값 교체

Sendway가 쓰는 비밀값은 **설정(환경변수·설정 파일)으로 주는 것**과 **관리 API로 등록해 데이터베이스에 두는 것** 두 종류이고, 교체 방법이 서로 다릅니다.

| 비밀값 | 두는 곳 | 교체 방법 | 옛 값이 멈추는 시점 |
|---|---|---|---|
| 관리자 키 | 설정 `Sendway:AdminApiKey` | 값을 바꾸고 재시작 | 재시작 |
| 데이터베이스 비밀번호 | 설정 `ConnectionStrings:Sendway` | 아래 순서 | 데이터베이스에서 바꾼 즉시 |
| 공용 채널 자격증명 | 설정 `Smtp:*`, `Fcm:*`, `Solapi:*` | 값을 바꾸고 재시작 | 재시작 |
| 테넌트 API 키 | 데이터베이스(해시) | `POST /admin/tenants/{id}/rotate-key` | 즉시 |
| 테넌트별 채널 자격증명 | 데이터베이스(암호화) | `PUT /admin/tenants/{id}/credentials/{channel}` | 다음 발송 |
| 웹훅 서명 비밀값 | 데이터베이스(암호화) | `PUT /admin/tenants/{id}/webhook`으로 다시 등록 | 다음 전달 |

### 설정으로 주는 값

설정은 프로세스가 시작할 때 읽으므로, 값을 바꾼 뒤 **재시작해야** 적용됩니다. 재시작하는 동안 접수된 메시지는 데이터베이스에 남아 있다가 이어서 발송되고, 그 사이 요청이 실패한 호출자는 같은 `Idempotency-Key`로 다시 요청하면 됩니다.

- **관리자 키** — 새 값은 충분히 긴 무작위 문자열로 만듭니다. 재시작 뒤 옛 키는 `401`입니다. 키를 쓰는 배포 스크립트나 감시 도구의 설정도 함께 바꿉니다.
- **데이터베이스 비밀번호** — 다음 순서로 합니다.
  1. 새 비밀번호를 넣은 연결 문자열을 배포 설정에 반영해 둡니다(아직 재시작하지 않습니다).
  2. 데이터베이스에서 비밀번호를 바꿉니다. PostgreSQL은 이미 열린 연결을 끊지 않으므로 실행 중인 프로세스는 계속 동작하지만, 새로 여는 연결은 실패하기 시작합니다.
  3. 곧바로 재시작합니다.

  연결 문자열에 들어가는 값이므로 새 비밀번호에는 `;`·`=`·따옴표를 쓰지 않는 편이 안전합니다.
- **공용 채널 자격증명** — 시작할 때 설정에 있는 `Smtp`·`Fcm`·`Solapi` 값이 저장된 공용 자격증명을 덮어씁니다. 설정에서 해당 항목을 아예 빼면 저장돼 있던 값이 그대로 남습니다.

재시작 뒤에는 새 관리자 키로 `GET /admin/queues`를 불러 봅니다 — `200`이면 관리자 키와 데이터베이스 연결이 함께 확인됩니다. 옛 키로는 `401`이어야 합니다.

### 관리 API로 등록하는 값

재시작 없이 바뀝니다.

- **테넌트 API 키** — `rotate-key`의 응답에 새 키가 한 번만 실려 옵니다. **옛 키는 그 순간부터 `401`이고 두 키가 함께 통하는 구간이 없습니다.** 그 테넌트의 서비스가 운영 중이면 새 키를 곧바로 배포할 준비를 해 두고 교체합니다 — 그 사이 그 서비스가 보낸 요청은 거절됩니다.
- **테넌트별 채널 자격증명** — 같은 채널에 다시 `PUT`하면 교체되고, 다음 발송부터 새 값을 씁니다. 재시도를 기다리던 메시지도 새 값으로 나갑니다.
- **웹훅 서명 비밀값** — 엔드포인트를 다시 등록하면 새 비밀값이 발급됩니다. 전달을 기다리던 이벤트도 새 비밀값으로 서명되므로, 받는 쪽의 비밀값을 함께 바꿉니다.

### 교체하지 않는 것

**Data Protection 키 링**(컨테이너 배포 시 `/data/dp-keys`)은 저장된 자격증명과 접수된 메시지 내용을 암호화하는 키입니다. 프레임워크가 주기적으로 새 키를 추가하고 옛 키는 복호화용으로 남겨 두므로 손으로 교체하지 않습니다. 이 디렉터리를 지우거나 잃으면 저장된 테넌트별 자격증명과 웹훅 비밀값을 읽을 수 없게 되어 다시 등록해야 합니다 — 데이터베이스와 함께 백업합니다.
